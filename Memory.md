- Preserve the goal of convenient personal use across devices when choosing dependencies, layout, storage, and deployment design.
- Using the app from several devices does not automatically imply that documents should sync between devices. No cross-device document storage/sync requirement has been specified.
- The phone screenshots establish an existing GitHub Pages copy on `skprasad628.github.io`, with the repository path truncated. Do not guess that path. - HTML, CSS, application logic, editor operations, and PDF loading are separated into files. The latest changes were made locally; this chat has performed no publishing, account configuration, or document synchronization. Deployment and subsequent physical-phone acceptance remain follow-ups.
- Native PDF rewrite responsibilities are split between `js/pdf-native-core.js`, `js/pdf-native-navigation.js`, `js/pdf-native-forms.js`, and `js/pdf-native-tags.js`, coordinated by `js/pdf-preserve.js`. Keep captured source leases, real output-page reference mappings, duplicate independence, reachable-graph validation, and explicit unsupported-feature rejection when extending this architecture. Exact untouched export must bypass rewriting so signed/encrypted source bytes remain intact. Do not turn a failed native export into an automatic raster fallback.
- The current `window.PageForgePreview` API provides `refresh()`, `clear()`, `zoom(number)`, `zoomIn()`, `zoomOut()`, and `fit()`; `zoom(number)` takes a factor from **1 to 4**, not a percentage. Keep zoom state separate from document/history/export state. Preview refreshes coalesce with animation frames and use request/content guards and source leases; **no ResizeObserver is used**. Keep the same page visible while preparing a sharper zoom rendering, hide old pixels when selecting a different page, reject stale success/failure callbacks, and release leases on every completion path. Pointer cancellation/lost capture must release panning state, and cached rendering must clear `aria-busy`.
- Keep browser pan/pinch eligibility on page-image surfaces and cancel hold reorders without a drop on scroll/multi-touch interruption. Scope callout/context-menu suppression to those images so ordinary controls and editable text retain native behavior. Crop interactions have their own exact source-space rectangle and rollback state.
- `cropPageBounds` and `cropToBounds` are per-page document metadata, not global layout preferences. Copy them through history, duplication, editor commits, preview captures, and immutable export queues. Default cropped sizing overrides paper/orientation/placement/margin only for that cropped page; disabling it restores global paper settings. Fresh sessions/New document still start at zero requested margin.
