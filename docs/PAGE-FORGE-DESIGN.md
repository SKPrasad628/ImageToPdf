## Typography and component tokens

- **Headings and brand:** Cinzel, followed by Georgia/serif fallback. Use measured letter spacing and occasional uppercase for short labels. Avoid long paragraphs in spaced uppercase.
- **Reading text:** EB Garamond, with Georgia/serif fallback, for atmospheric prose and supporting narrative. Compact technical values, filenames, and controls use a system UI stack for scanning; keep these large and readable at browser zoom. Native fallback remains available if a local font fails.
- **Font delivery:** local files under `vendor/fonts/`, declared in `css/fonts.css` with `font-display: swap`. Retain the SIL Open Font Licenses and font provenance. No Google Fonts stylesheet or third-party font request at runtime.
- **Surfaces:** quiet navy panels, thin rules, restrained blue shadowing, and modest corner rounding where useful. Intake uses one dashed outline; repeated frames, ornaments, and glowing borders are reduced. Retain the engraved brand emblem and sparse gold details. Decorative corners must not reduce button hit areas.
- **Spacing:** organize controls into clear groups with consistent gaps; give the paper preview room to breathe. Keep supporting controls subordinate to the active page and Forge PDF action.
- **Controls:** native labeled inputs/selects and real buttons. Use visible focus, adequate contrast, and touch targets around 44 CSS pixels. Keep Edit page, Rotate, and Page actions visible; put less frequent controls in named menus or disclosures. Actions must remain reachable without hover or dragging.
- **Text carets:** ordinary interface text inherits `caret-color: transparent`. Inputs, textareas, and editable content restore `caret-color: auto`, including empty, true, and plaintext-only `contenteditable` values; explicit `contenteditable="false"` stays transparent. Preserve normal field carets, text selection, and keyboard focus rather than suppressing selection or focus globally.
- **Motion:** short, understated border/opacity transitions, a restrained circular progress ornament, and respect `prefers-reduced-motion`. Progress remains understandable from text when animation is off.

Keep transactional PDF imports, cancellation, filename/type detection, limits, password handling, and persistent rejected-file reporting.

Supported intake and limits come from the production engine: JPEG, PNG, WebP, GIF, and BMP with verifiable dimensions, plus PDF. Image source caps are 256 MiB, 256 megapixels, and 65,535 pixels per side. Inputs exceeding working dimensions or available encoded storage are automatically fitted without upscaling to at most 16 megapixels and 8,192 pixels per side. Fitted images use lossless PNG and can be reduced further to meet the 32 MiB per-image cap and shared 128 MiB retained budget. Smaller images keep their original bytes. PDF inputs retain a 50 MiB limit; documents contain at most 200 pages. Aggregate raster export remains limited to 64 megapixels and generated output to 128 MiB. Unsupported formats receive actionable reasons. Do not promise TIFF, SVG, AVIF, or arbitrary `image/*` browser decoding when the current safety checks reject them.

Show automatic fitting in the persistent import report, with original and working dimensions. The active-page and editor notices explain that editing, Revert, and Preserve original quality use the working copy; the device original is unchanged. Keep these factual notices in ordinary technical language. Normalization shares the ordered decode queue, supports cancellation, and uses a dedicated worker where available with a bounded asynchronous fallback. A native decoder can still fail on a valid large source; report that failure clearly instead of allocating an unbounded full-size HTML image.

### 5. Forge and recover

The main action invokes the existing shared export pipeline with an immutable capture of pages and settings. Prevent simultaneous export starts; progress and disabled state must remain coherent. Retain URL/source leases so live edits or clearing do not corrupt an in-flight export.

Replacing output, resetting results, creating a new document, or `pagehide` releases URL/reservation ownership exactly once. Navigation into the back/forward cache also triggers cleanup; returning restores the preview but requires forging again to restore the in-tab download action. An already downloaded file remains on the device. Failed initial download setup does not retain a URL or reservation.

New document and Continue editing actions must preserve the existing clear/undo rules and avoid unexplained data loss. Uploaded documents and generated output stay in the tab; no cross-device sync or saved document library is promised.
